# 20个成就小游戏的实际规则检查

`MinigameRulesRuntime` 对GameMode 1..20逐一执行100、30、240Hz与不规则纳秒步长，共80个场景。使用真实Board::InitLevel／StartLevel和Board::Update，独立临时PlayerInfo，不打开游戏窗口、不读取用户进度；每种模式末尾额外检查暂停时Board时间不随Visual推进。

这不是一次自动打通所有关卡的测试。以下明确区分实际操作、边界调用和其他证据；没有把初始化不崩溃当作玩法验收。

## 本次修复与原版证据

- **传送后跳回入口**：现代直线运动按旧出生时间／坐标求值，传送只更新位置和根运动绑定，没有结束直线段。[修复前输出](portal-before-fix.txt)记录气球出口X=664、下一拍X=125.27而行号仍是出口行。现在传送使X／Y直线基准失效；Zamboni的X槽存爆胎速度基准，保留其时间和速率。1073在`0x429C14/0x429C17`同步出口整数／浮点X，随后更新行号及Y，不存在现代运动基准。
- **脑子永远不被吃／立即可吃**：现代脑子保存出生纳秒，但找食物条件仍读取union中的32位mBrainHealth，出生为0时永远达不到旧计数15；非零出生时间又可能立即超过15。[修复前输出](aquarium-before-fix.txt)保留实际饥饿鱼10秒不吃的失败。改用传入当前时间减出生时间，门槛150000000ns，不增加字段或改变v4布局。I-Zombie脑子仍是独立类型的70次啃食计数。

`extract.py`以SHA256锁定1073发行EXE，只读解码已验证的指令边界。[指令输出](retail-disassembly.txt)含脑子计数初始化、每次Update递增、食物类型及至少15的过滤，以及传送坐标同步。原版阈值是15次计数；本项目用纳秒年龄表达该时长，不恢复固定tick子模拟。左右键、5阳光与最多3个脑子的原版证据见[前一批模式核对](../minigame-behavior-1073-20261101/README.md)。
