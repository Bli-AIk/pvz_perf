# 玉米加农炮多指与移动拾取验证

日期：2026-11-03。本轮只在本机验证；手机按用户要求保持不动。Windows Vulkan Release 已构建（/GL、/LTCG），夹具链接同一批生产对象并读取实际 PAK。Android ARM64 原生库只做本机交叉编译，未安装或宣称实机验收。

`touch-input.log` 中的 cannon touch/pickup PASS 覆盖：

- 两指分别选择两门就绪炮，点击第一门的右半格也能命中。
- 炮前重叠的阳光／金币立即拾取，但触点仍选择对应炮。
- 拖动线段经过银币和阳光，两个端点都不在命中区时仍能拾取；不改炮目标和鼠标坐标。
- 第三根不持炮的手指经过金币仍能拾取，不打断前两指瞄准。
- 先松第一指，第二指继续移动和松开，各炮只进入一次发射状态，分别记录正确目标。迟到的抬指不重复发射。
- 同炮重复认领被拒绝；单指取消不取消另一门炮。
- 短点保留 A 炮后，尝试认领另一手指占用的 B 炮被拒绝，不误发或替换保留的 A 炮。
- 两门炮瞄准中实际保存，触点取消且两炮仍就绪，不把触控准心写入 DAT64。
- 鼠标持有的炮不能被新触点抢走；鼠标在触控瞄准之后又选中同炮时，先发射者生效，第二次提交不触发原来的 READY 断言，也不改写目标。
- 瞄准中的炮实际 Die 并经过 ProcessDeleteQueue 后，松手不会访问旧对象。
- 暂停时移动不拾取；恢复后经过可以拾取。已经在收取的金币不会重复重置收取起点。

共用命中范围的回归遍历全部 CoinType，在普通和锤僵尸规则下分别检查鼠标边界表达式和触控点命中；礼包、钱袋、奖杯、掉落卡片不被移动拾取。线段测试还区分真正穿过矩形、仅包围盒相交、排除的右／下边界、已死亡与已收取对象。

同次实际夹具还通过原有触控、按钮捕获、用户列表、共享植物／铲子状态、保存读取和 800／1400 宽度选卡 Menu 回归，以及图形公共前置项。这里没有记录整局帧率、微基准提升倍率或手机性能结论。

此轮没有新增存档字段：只在不序列化的 BoardTouchContact 中增加 cannon 标记，Coin 没有新增数据成员。源码、Release、夹具、PAK 和 Android 原生库 SHA256 见 manifest.json。
