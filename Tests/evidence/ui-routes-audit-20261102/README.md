# 图鉴预览、对象出生时钟与关卡结算

测试链接当前Release/LTO生产对象和实际PAK；隐藏窗口只提供真实GPU渲染目标，玩家存档与资料写入Temp私有目录。没有操作玩家正在运行的游戏。

## 图鉴：75个可选预览 × 16种上下文

49种植物、26种僵尸，分别在主菜单／关卡内、800／1400宽度、100／30／240Hz及不规则步长下核对，共1200个页面检查。

通过实际DoAlmanacDialog、图标命中与MouseDown选中每项，运行实际LawnApp::UpdateFrames和Almanac更新。每页实际渲染两次：预览在正常位置，以及仅将该预览移到屏幕外；要求可见像素不同，避免把背景或图标误认作预览。两次之间不推进时钟。此对拍证明该预览有可见贡献，不是原版逐像素或姿态几何的独立oracle。

每个上下文都检查索引页动画、回到索引、关闭释放。关卡内保留一株真实豌豆射手，确认整个图鉴访问中Board时钟及其动画相位保持；关闭后仅按7891011ns的一次实际更新恢复，不补算浏览图鉴的时间。预览本身始终没有Board指针。解锁资料与缩略图缓存由夹具提供，使用实际缓存预建入口；首次夹具缺缓存的错误不作为游戏缺陷。

修复前before-almanac.txt中的八个主菜单上下文通过，八个关卡内上下文均在索引页动画检查失败。根因是LawnApp暂停Board时同时冻结共享Visual时间，图鉴读取该时间。现在图鉴打开时与商店一样放行UI时钟，Board/Battle保持暂停；普通暂停的Visual冻结行为不变，无新增字段或存档更改。

1073的0x402F50图鉴更新先更新按钮，0x402F8D直接调用Plant::Update（0x467880），0x402F9C直接调用Zombie::Update（0x53B750），没有Board暂停判断。0x403089增加图鉴使用的水面计数。这些地址只说明已核实的图鉴局部控制流，不把旧源码地址注释当作证据。

## 创建时绑定动画时钟：620种上下文

关闭图鉴的首步检查进一步复现了另一个问题：新建豌豆在第一次交给Board更新时，所属时钟才从默认Visual变为Battle。该切换将起点平移到更新末端，造成Board推进7891011ns而相位仍为0。before-birth-resume.txt记录实际值；它是丢掉首步，不是补算暂停时间。

53种植物、34种僵尸的战场／街头／UI创建，分别在开场／战斗、零／非零Board时间下核对，共620种上下文。修复前before-birth.txt中174种战斗创建失败，恰好为(53+34)×两种出生时间；其余Visual创建通过。当前Board::NewPlant和AddZombieInRow在初始化后立即按管理者时钟绑定所有动画字段，含雪橇随从及僵尸附属动画。首个实际Board::UpdateGameObjects检查另用普通豌豆和普通僵尸，确认第一步年龄确实被消费。

没有增加字段或更改存档，也没有给Plant／Zombie接口添加时间域参数。绑定工作只增加在创建处，不增加每次更新的扫描。

## 冒险奖励：50关 × 首周目／重玩 × 四种步长

400项通过实际CheckForGameEnd、资料更新、奖励屏幕淡入及StartButtonPressed，检查下一关／下一周目／场景正确：

- 首周目每关显示对应奖励；重玩普通关直接进入下一关，纸条等保留奖励页的边界仍显示。
- 第14关结束后的图鉴介绍，走真实关闭按钮命中及嵌套WaitForResult返回。
- 第24／34／41关结束后的商店分别从301／601／3100开始，真实更新Dave入场、逐次空格推进对白，等按钮可交互后返回。
- 第44关结束后进入花园教学，Dave从2100开始；最终关经过纸条进入Credits。

关卡完成标志直接构造，历史成就全部设为已展示以隔离主奖励路由；没有把这些跳转写成400次整场战斗，也没有覆盖未展示成就叠加、输入中断或试玩版购买分支。最初图鉴关闭夹具只写旧悬停字段，未设置当前逻辑鼠标位置，被真实命中函数正确拒绝；夹具已改为按钮中心的实际鼠标坐标，生产代码未因此修改。

## 失败结算：224种上下文

冒险六种背景、Pogo Party、普通／无尽生存走真实进家过场；水族馆、Last Stand、我是僵尸及两种无尽解谜走真实直接失败框。两种宽度、四种步长分别检查重试与返回菜单，共224项。触发使用实际ZombiesWon入口，失败边界由夹具构造，没有完整模拟清场／饥饿。

进家过场保持Board/Battle时间，电影动画确实推进，约11秒后只创建一个Game Over；直接失败框立即出现。继续三次更新不重复创建、不推进冻结时钟，实际绘制战场和失败框后按真实按钮回调重试或回到正确页面，核对关卡进度不因失败前进。

初版夹具给水族馆添加了普通进家僵尸，错误触发缺失aquarium动画轨道的硬错误；水族馆只支持其潜水鱼，真实失败入口传nullptr。夹具现按两类失败入口设置，生产轨道检查没有放宽。另发现原版1073的ZombieWonClick在0x43FB69清理Board，冒险分支0x43FB79调用NewGame，0x43FB81随后再次跳转NewGame；此处异常的双初始化确实存在于发行EXE，未擅自当作新缺陷删除。

## 正常开场：720种上下文

冒险50关首周目／重玩共400项，其余70种可玩模式各四种步长共280项，另40项升级卡槽分支。独立实现文件OpeningFlowRuntimeChecks.cpp链接实际生产对象；使用真实PreNewGame、首次Board绘制和UpdateFrames推进，逐次空格通过戴夫对白，等待卡片飞行并调用真实Start按钮，确认正常进入Playing，开场时间没有泄漏到Battle。首次保龄球实际拿铲子挖掉三株豌豆，不直接跳过教学。Intro演示和CUSTOM保留槽不混入这70种关卡，前者有独立检查，后者没有原版可玩入口。

普通资料没有购买资金以隔离可选升级，卡片取当前可用且允许的类型；不满足推荐搭配时，通过真实警告确认继续。额外覆盖第13／16关首、次卡槽的接受／拒绝／确认前余额归零，以及第13关已购首槽时不重复推销。没有CancelIntro来替代被测开场，也没有人工设置Playing绕过这些720项交接。使用控制资料、自动快速点击，不替代文字可读性、听音或真人节奏验收。

## 僵王损伤／死亡与花园售花：16种上下文

冒险最终关和僵王小游戏各四种步长，真实受伤入口依次跨过80%和50%生命门槛，检查自动进入蹦极／砸车并回到待机，再施加致命伤，经过死亡动画到恰好一个实际关卡奖励。血量由夹具施加，防守植物高生命；不把这八项写成玩家完整作战或所有随机选招覆盖。此前五种攻击的定向检查仍分别保留。

花园八项分别确认／取消实际卖花对话，检查余额、资料数组压缩、存活植物索引，以及卖花时配套花盆一并移除。最初夹具把没有盆栽资料索引的辅助花盆当作错误植物，现已按生产的独立花盆模型核对；这不是生产缺陷，也没有放宽资料索引检查。

定向入口为tools/test-image-runtime.ps1的ui-rules（图鉴和奖励）、award-rules、almanac-clock（仅时钟）、actor-birth、loss-rules、opening-rules或lifecycle-rules。capture.py要求完整运行时套件通过、组合无遗漏，归档原始输出以及源码、测试exe、PAK哈希。extract.py校验1073哈希后生成局部指令文本。全部结果属于功能检查，不产生性能或手机实测结论。
