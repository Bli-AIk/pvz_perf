# Windows 触点输入首阶段验证

首阶段源码在 Windows x64 Vulkan Release 下构建，使用 `/GL` 和 `/LTCG`。侧键 1／2 共用一个模拟触点；运行时捕获及 Board 上下文保留十个 ID 槽。DAT64 保持 v4.0。

`touch-input.log` 来自 `tools/test-image-runtime.ps1 -Case touch-input`，链接生产对象、读取实际 `main.pak64`。触点检查通过，覆盖：

- 不同 ID 分别捕获控件；移动越过另一控件仍交给原控件，坐标转为局部坐标；鼠标捕获保持独立。
- 按钮移出松开和取消不点击；移除控件、暂停和越界松开清理捕获及持有卡片。
- 两个触点和鼠标同时持有三张不同卡，独立预览，松开只种一次，提交时再次核对阳光。
- 保存时归还触点卡片，真实 v4 保存与重载保留盘面；在按下回调内部保存仍写入真实鼠标光标。
- 隐藏窗口中的实际侧键适配使用呈现矩形反算坐标；两颗侧键共用一次按下、最后一次松开。
- 掉落卡片被移除后松开不解引用失效对象；传送带移除前方卡片后调整持有卡片的索引与占用状态。
- 砸僵尸的触点锤子独立创建、释放与再次使用。

同次检查的图像公共前置项也通过，见日志中的逐项 PASS。另已重建并通过 `pvz_time_counter_save`、`pvz_v7_save_schema`。源码、生产 EXE、PAK 和夹具 EXE 的 SHA256 记录在 `manifest.json`。

同一夹具 EXE 的 `ui-rules` 回归通过：菜单／关卡内图鉴在 800、1400 两种宽度及四种步长下完成 1,200 个植物／僵尸预览场景，并完成 400 条冒险奖励跳转，含嵌套图鉴／商店输入、花园教学及 Credits。完整输出保存在 `ui-rules.log`，不将它算作触屏实机验收。

这是生产对象的自动化回归，不是物理触屏或多指实机测试。Windows 的原生触屏事件、Android 多指事件、横板 UI 和各小游戏的专属多指手势尚未验收。侧键实际操作手感由人工试用确认。

此目录保留 Windows 首阶段的历史产物与源码哈希。Android 原生事件和后续“触控不借用鼠标坐标”的验证见 [Android 触控回归](../android-touch-input-20261103/README.md)。
