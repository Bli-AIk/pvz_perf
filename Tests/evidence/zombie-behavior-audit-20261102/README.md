# 僵尸主要行为逐项核对

范围是 `NUM_ZOMBIE_TYPES` 内34种实际僵尸，每种分别运行100、30、240Hz和不规则纳秒步长，共136个主要行为场景。另有五种定身恢复夹具、每种四套步长，共20项。缓存撑杆和枚举哨兵不计入分母。运行时检查场景名单没有重复、遗漏；`capture.py` 再独立核对136条输出的类型与步长组合。

海豚另外记录四种步长下自然入水的切换前后坐标，确认向左70像素的平移保留、随后一拍继续向左：100Hz切换步为−70.9074、下一步为−0.907410像素；30Hz为−73.0247／−3.02478；240Hz为−70.3781／−0.378052；抖动为−70.4929／−1.00824。未复现旧直线基准把此偏移覆盖的疑点，没有因此修改生产逻辑。

使用真实 Board、Zombie、Plant、Projectile、Reanimation 和粒子资源，并调用生产对象更新，未用另一份运动公式代替被测代码。

- 普通、旗帜、路障、铁桶、铁门、橄榄球、游泳圈、小鬼、自定义旗帜及坚果头：行走到目标并造成啃食伤害。报纸额外破坏纸盾，检查发怒恢复。
- 撑杆：触发起跳、落地、失去撑杆，检查没有直接进家。潜水／海豚从泳池入口开始，检查入水后浮起啃食／跳过目标。气球和跳跳检查越过植物，不以啃食代替其动作。
- 冰车检查碾压和冰道；雪橇检查四人关联、失去冰道后解体。矿工缩短初始地道距离，仍经历钻出、转身、向右移动。雪人经历倒计时后转身逃跑。
- 舞王在中行完成召唤四名伴舞；单独伴舞另外检查移动／啃食。夹具同时推进应用时钟，避免把本来读取该时钟的舞步冻结在一个阶段。
- 蹦极从真实目标选择开始，经历下降、抓取、带走。梯子僵尸检查放梯和失去梯盾。巨人／红眼先砸植物，再通过实际伤害越过半血线并扔出一只小鬼。
- 豌豆／机枪头检查首轮一发／四发，辣椒头检查烧行和消耗，倭瓜头检查起跳、落下、压扁目标。压扁是状态变化，植物延迟删除，不能把即时删除当作正确行为。
- 投篮僵尸实际投出20颗篮球，每次完成投掷只扣一个弹药，耗尽后恢复行走不瞬移。
- 僵王自然入场并召唤第一只普通僵尸；随后从公开攻击入口分别启动吐球、砸车、蹦极和踩踏，等待每种动作返回空闲。检查球／僵尸／压扁状态确实出现；没有验证随机选招分布、所有血量阶段或死亡结算。

目标使用高生命植物以隔离僵尸动作。部分起始位置缩短了路程；僵王不是从头打到通关。测试只证明这些主要行为链和明示的状态边界，不代表全部地形、交互、存档组合及关卡模式已经验收，也不产生性能结论。

## 本次发现和修复

1. 投篮复用 `mSummonCounter` 存弹药。`--` 随纳秒步长扣计时，不能用于每次扣一发；改成显式减一个常量单位，保留现有磁盘表示。[1073指令](retail-disassembly.txt)在 `0x533302` 初始化20，`0x536128` 每次投掷完成执行一次整数DEC。`extract.py` 校验发行EXE哈希，不运行或修改原程序。
2. 停走期间旧直线运动段继续保留出生时刻。投篮耗尽后重新采样，把几十秒投篮时间补成位移；修复前100Hz实际流程从约650跳到−784并切入失败场景。[修复前输出](catapult-before-fix.txt)保留原始失败。现在停走时结束旧运动段。
3. 黄油／冰冻使动作和位置更新被跳过，同样不能让旧运动段在恢复时补算冻结时间。已用黄油复现投篮僵尸恢复时约98像素跳变；现在定身分支使X／Y／高度线性基准失效，并让根运动重新绑定当前位置。五种夹具包含投篮、潜水、海豚、有额外线性偏移的普通根运动和游泳圈入水高度，检查冻结保持和恢复单步变化。没有新增实例字段或修改存档布局。
