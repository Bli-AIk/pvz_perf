# 已生效修复

这里只记录当前仍有效的缺陷根因和处理方式，不保存排障聊天、临时包路径或安装等待记录。
运行机制以[运行时](runtime.md)为准，回归入口以[验证说明](validation.md)为准；
原版行为证据保留在[调查目录](research/README.md)。

## 时钟与动作

| 问题 | 根因与现行处理 |
| --- | --- |
| 高目标帧率使游戏缓速 | 把每拍当成固定模拟步长。现在累计实际墙钟纳秒，处理完整实际时间，超时不额外sleep，节拍余量用于后续补偿 |
| 撑杆落地瞬移、屋顶小鬼二次升空 | 动作段切换后仍使用旧运动起点或重复应用屋顶修正。事件处重绑运动基准，保持当前实际位置连续 |
| 定身、停走后僵尸位移异常 | 根运动基准与已处理动画状态失配。变速和动作切换时保留局部进度，不把未经更新的管理者时间当作已处理相位 |
| 末帧保持动画读档报历史相位越界 | 保持末帧状态与普通循环区间不同，保存／恢复必须按动作边界重建缓存，不能把周期上界直接当普通余数 |
| 双发／机枪／忧郁发射漏轮 | 宽步长一次跨越多个发射阈值，或后一发覆盖待执行的第一发。保留触发次序并分别消费事件，不靠提高TPS掩盖 |
| 图鉴、商店、礼盒和Credits的动画冻结或崩溃 | 非战斗对象隐式访问Board，或继承了已暂停战斗的时钟。由对象的管理者从创建到更新显式传入一致时间 |
| 无尽选卡水面状态不一致 | 新关卡首次入场使用Visual，首次开战后交给Board；普通暂停和后续选卡保留战斗相位，寒冰菇另有冻结规则 |
| 开场关卡名消失过晚 | 有限时长提示误用冻结的战斗基准。以关卡入场Visual时间为起点，计满自身显示时长后失效 |
| 暂停框报纸僵尸不动 | 暂停框属于暂停状态本身，动画由墙钟推进，不使用被冻结的Board时钟 |

Reanimation的帧缓存与根运动是现行生产机制；旧的逐Zombie候选布局、倒数缓存和线程流水线
不是现行实现。普通钱币、阳光、投掷物、割草机和按钮按纳秒步长模拟，不能把已撤销的
指数运动／100Hz采样表再次写成当前方案。粒子只保留离散模拟；出生年龄由传入时间求差。

## 玩法与输入

| 问题 | 根因与现行处理 |
| --- | --- |
| 横板UI教学反复提示种豌豆／向日葵 | 横板冷却闪光提前返回，跳过教学状态推进。两种布局共用推进规则；成功种植能结束对应提示 |
| 冷却卡牌随阳光数量变色 | 冷却外观误混入费用条件。冷却时统一浅灰，结束后再判断费用及种植条件 |
| 僵尸快跑模式只有部分内容加速 | 按原模式的更新顺序处理战斗子更新，不只缩放场景动画或阳光时间 |
| 水族馆拾取阳光时放脑子 | 记录本次手势是否拾取，仅限制脑子投放，不妨碍其他输入；投放仍走模式专属业务 |
| Twist、拉霸、阳光拾取目标或震动横向错位 | 把Board镜头偏移误套给固定HUD。场景、HUD和窗口各自使用对应坐标，恢复Graphics状态时不重复累计偏移 |
| 选卡页返回后滚轮失效 | 模态菜单、商店、图鉴、模仿者退出后焦点还给Board。现在还给当前选卡页 |
| 触控点击依赖鼠标悬停 | 事件处理误读全局鼠标位置。鼠标与触控分离，点击按事件坐标命中，手势固定捕获按下对象 |
| 触控卡牌／铲子选择冲突 | 多指各保留一套选中状态。现在共用一个选择，失败拖放保留选择，再次点选可取消；鼠标也复用该选择 |
| 初始墓碑隐形 | Board尚未推进时升起动画停在起点。初始墓碑直接处于完整升起状态；战斗中新生墓碑仍走对应业务 |
| 巨人关键区间定身的ICE3／ICE4 | 保留原版中断顺序和重试语义，不作为需要消除的业务缺陷。原理、如何有意移除此行为见代码注释和[调查](research/ice3-interruption.md) |

## 图像、资源与生命周期

| 问题 | 根因与现行处理 |
| --- | --- |
| 局部静态表未静态存储导致额外开销 | 相关只读分发表明确使用static constexpr。这是本项目实现缺陷，不列作超越原版的性能优化 |
| 粒子／reanim外观或纹理错乱 | 定义、UV和加载绑定必须同源，保留变体与共享图集的对应关系；运行时不再逐轨道覆写全局纹理符号 |
| 手机图集边缘白点、噬碑藤白缝 | 对实际上传的普通图像执行透明边缘修补，并修正采样区域；生成图像与特殊滤镜保留自己的采样契约 |
| 种子冷却、草卷、Credits裁剪失效 | 必要业务裁剪不能一律取消。明确裁剪入口与无裁剪入口并存，文字测量不通过空目标绘制实现 |
| Credits泳池／灯光偏左或越界 | 保持居中800×600影片区；平移和裁剪沿当前Graphics传入。Replay单独按窗口左侧布局 |
| Quit确认框抛Unknown exception | 文字测量触发要求GPU目标的绘制路径。折行计高独立完成，不提交字形绘制 |
| 释放或读档后悬空资源 | 构造失败回收部分资源，GPU引用按完成信号延迟释放；读档重建派生缓存和绑定，不恢复进程指针 |
| 启动时窗口显示无响应 | 加载、主循环和消息泵的职责不能由错误门控阻断。等待加载或空闲时保持窗口事件处理，避免把恢复后的积压墙钟一次灌入战斗 |

## 平台与音频

- Android的Surface变化、小窗和翻转统一更新视口及触点映射；系统标题栏不由游戏绘制。
  英文输入使用原验证路径，非ASCII输入不进入旧字形索引；返回键按Esc处理。
- Android字幕／音乐加载遵守装载线程发布边界；BASS音量参数按接口类型传入，避免把整数位模式当浮点音量。
- Web的MO3解码器把首行处理推迟到read，恢复BPM／speed之前必须先处理并保留首个采样帧；
  属性查询等待音频线程确认，读档和暂停恢复共用。原生BASS不走Web适配层。
- Web宿主抢焦点或取消指针捕获时释放当前手势；点击canvas恢复焦点，暂停按钮不依赖旧鼠标位置。
- Windows图形后端不因Android条件编译遗漏镜像／上传；旧系统动态入口与运行时依赖单独审计。
- 图形主帧使用双槽位并非复制所有纹理，详见[GPU提交](gpu-submission.md)。

## 存档边界

当前关卡为DAT64 v4，用户资料为PVZUSR64 v13。转换器只支持文档列明的正式格式，
不把未发布的中间版本当兼容承诺。完美资料与无尽基准由独立生成器生产，完美资料购买坚果包扎术；
不把开发者正在游玩的进度打进发行包。具体协议、转换与目录见[存档说明](DAT-DAT64-CONVERSION.md)。
