# v3.3.2

本次发布四个原生平台包：`x64-win10-vulkan1.3`、`x64-win7-openGL3.3`、
`arm64-android14-vulkan1.3`、`arm64-android7-vulkan1.0`。Web 源码进入本次提交，
仍属试验平台，不上传 Web 发行包，也不更新已上传的 Toy。

## 修复

- 横板 UI 的卡牌冷却闪光不再提前退出教学推进。冒险 1-1 种植豌豆射手、1-2
  种植向日葵后能结束相应提示；成功种植也能推进停留在取卡／等待冷却状态的教学。
- 冷却中的卡牌统一浅灰显示，不再随阳光是否足够改变。冷却结束后仍按阳光和种植条件
  判断可用性；桌面与横板布局共用规则。
- 重新生成完美用户档与泳池无尽基准附带的用户资料，补上坚果包扎术购买标记。
  四个平台的整包均附带这份完美进度和统一无尽起点。
- 重新构建 Win7／OpenGL：两套动态顶点流轮换，支持 core 3.2／ARB_sync 时
  零等待检查对应 fence，未完成仅延期绘制；移除主画面每帧的 glFinish。
  纹理、图集、场景目标和静态索引继续共用，不复制整套素材。

## 图形后端与 Web 源码

- Vulkan 保留双槽位、非阻塞复用；GL／WebGL 共用双槽位实现。旧 GL 3.0
  无 ARB_sync 时保留驱动管理的 BufferData 存储替换，不硬要求新入口。
- DX12 分离两套 allocator、command list、动态上传流、临时描述符和延迟释放资源；
  纹理描述符只向空闲帧槽同步发生变化的项。DX9 使用两个 event query 和动态顶点流。
- Metal 源码加入双槽位及可复用的顶点／argument buffer，四顶点矩形共用静态16位索引。
  本机无 Apple SDK 或 Metal 设备，该部分未经编译及实机认证，不发布 Metal 二进制。
- Web 改为配合 requestAnimationFrame 调度，避免计时器循环在浏览器两次重绘间反复提交。
  修复 MO3 定位后首行命令覆盖恢复速率的问题，覆盖读档与暂停恢复；原生 BASS 不受影响。
- Web 两个领取入口默认检查关注状态，作者本人可通过；离线配置绕过检查。
  阵型清单当前仅含泳池无尽测试基准，去除 Edition／性能版字样。

OpenGL、DX12、DX9 渲染回归及浏览器回归分别验证，不把某一后端的结果用于替其他后端背书。
没有重测无尽整局收益；桌面受控绘制小测试不作为新的正式整局性能数据。

## 存档与平台

继续使用 DAT64 v4（schema 0x10745）、PVZUSR64 v13。本次未增加存档字段，
可以继续使用 v3.3／v3.3.1 的现有存档；导入完美档会替换目标用户资料，导入无尽档
还会替换相应关卡进度。每次性能比较前请重新导入统一起点。

仍沿用 v3.0 对 v1.x／v2.x 的资源和存档不兼容边界。旧档须使用附带转换器，
程序、shader 与 main.pak64 请使用同一发行包，勿跨版本混配。

Android 14 包要求 Vulkan 1.3，Android 7 包使用 Vulkan 1.0 兼容路径；
两个 APK 均关闭 HDR。Windows 默认自动跟随屏幕刷新率、不启用横板 UI；
Android 首次创建配置时默认跟随刷新率并启用横板 UI，已有配置不覆盖。
