# 巨人投掷与锤击关键帧的定身中断（ICE3／ICE4）

2026-11-03～04，当前 Vulkan Release 对象与生产 `main.pak64` 验证。

普通巨人与红眼巨人的投掷事件位于 `anim_throw` 的 0.74 相位。动作读到跨过该相位的区间前，如果被冰或黄油定住，原来的动作检查会被跳过；恢复后继续完成这次空投动作、收手，再因仍携带小鬼而重新投掷。这里保留的是这个漏事件并重试的行为，不把漏掉的事件积压到解冻时补发。

锤击对应 `anim_smash` 的 0.64 相位。ICE4 同样要求漏掉本轮命中，恢复后收手，再因目标仍在而重锤；普通暂停后在同一轮继续命中不算 ICE4。[冰代奏说明](https://wiki.pvz1.com/doku.php?id=%E6%94%BB%E7%95%A5:%E5%86%B0%E4%BB%A3%E5%A5%8F&redirect=1#ice3) 将 ICE3 的炮后时刻列为原速106cs／减速211cs，ICE4 的垫材种植时刻列为原速134cs／减速266cs；这是战术操作时刻，不能直接等同于本夹具内的动画相位。

## 定位与修复

历史实现位于邻近原版树 `_win32-replacement-20261014/before-a/Lawn/Zombie.cpp` 与 `Sexy.TodLib/Reanimator.cpp`：`UpdatePlaying` 在未定身时执行 `UpdateActions`，随后僵尸的附件动画才更新；`ShouldTriggerTimedEvent` 读取上次动画区间，并在动画速率非正时返回 false。该树含后续改动，只作为机制参考。旧函数注释地址不构成 1.2.0.1073 二进制取证，本报告也不声称已对零售 EXE 的 ICE3 路径进行逐指令验证。

现代代码为精确根运动在 `Zombie::Update` 入口提前 `PrepareTimeAt`。对巨人而言，这会在动作读取前覆盖上一动画区间，原有中断窗口因此消失。

最初的修复只让存活、在场的普通／红眼巨人跳过 body 动画预推进。随后按用户要求统一为所有僵尸的动作顺序：删除 `Zombie::Update` 入口的预推进循环，在 `UpdatePlaying` 中先执行 `UpdateActions`，再把原有五个动画引用的预推进循环放到 `UpdateZombiePosition` 前。没有新增巨人类型分支。于是：

- 投掷和砸击的动作检查读取上一动画区间，定身时仍跳过动作检查。
- 行走位置仍读取当前时刻的根运动，未改为速度逐帧累加，也未降低动画时钟精度。
- 所有僵尸的常规动作都先读取上一动画区间；是否可定身、是否重试仍取决于各自动作状态机，不承诺每种僵尸都存在巨人式的重试动作。
- 非常规路径（例如死亡、场外预览）由既有 `UpdateReanim`／附件路径完成动画更新，不再在 `Zombie::Update` 入口统一预推进。
- 未增加成员、延迟事件队列或存档字段。

`UpdatePlaying` 中的长注释说明了事件丢失的时序、与植物／投射物更新顺序的关系，以及改版若有意删除这一中断窗口，应把完整预推进循环移回动作分派之前并重新验证各动作，不能仅调整巨人阈值或在解冻后补发事件。

## 运行验证

`Tests/native/ImageRuntimeTests.cpp` 的 `ZombieBehaviorCatalogRuntime` 包含 24 个定向案例：普通／红眼巨人 × 100、30、240 Hz 与不规则步长 × 无定身、冰、黄油。夹具直接启动投掷，等待 0.74 事件区间已就绪但尚未被动作消费。冰在下一次植物先于僵尸的位置施加；黄油在上一帧僵尸之后的投射物位置施加。每次只施加一次定身。

无定身组要求首轮投出一个小鬼，不经历收手重试。冰／黄油组要求首次动作结束、再次进入投掷后才投出一个小鬼，且 `mHasObject` 清除。测试通过真实 `Board::UpdateGameObjects`、状态接口和动画附件更新，不以手工更改最后动画区间制造漏事件。

ICE4 另有相同矩阵的24项。夹具先用真实 `FindPlantTarget` 确认墙果处于砸击范围，再启动锤击，在0.64区间施加一次冰／黄油。控制组要求首轮将墙果砸扁；定身组明确要求首轮结束、巨人回到普通状态时墙果仍未死亡且未砸扁，随后自动重入锤击动作，第二轮才能出现真实 `mSquished`。日志同时记录 `finishedFirst`、`retried` 与 `squished`。`Plant::Squish` 会保留扁图5秒才死亡，因此即时命中依据为 `mSquished`，不以延迟死亡或相位变化单独判定命中。

| 验证 | 结果 |
| --- | --- |
| `-Case ice3`（同时运行ICE3／ICE4） | 48/48 通过，各24项 |
| 完整 `zombie-behavior` | ICE4追加后复跑通过，含上述48项、32种主行为、20发投篮车、定身后的根运动／线性运动／高度恢复，以及僵王主要动作，均覆盖四种步长 |
| `pvz_frame_timing`、`pvz_slot_machine_clock`、`pvz_reanim_clock`、`pvz_plant_launch_clock` | 4/4 通过 |

复现定向用例：

```powershell
./tools/test-image-runtime.ps1 -BuildDirectory out/x64-win32-vulkan -Case ice3
```

## 边界

本轮验证的是投掷／锤击关键区间被中断后的机制，不承诺原版社区所述的106cs／211cs、134cs／266cs等精确操作时刻，也未测量1073浮点累计误差形成的逐帧边界。30／240 Hz 下窗口按更新区间存在，不强制量化成100 Hz。夹具调用真实冰／黄油状态接口，但没有覆盖完整冰菇爆炸与黄油弹飞行的端到端时刻。

统一所有僵尸顺序后已重新构建 Vulkan Release，48项 ICE3／ICE4与完整 `zombie-behavior` 再次通过，包含投篮车、32种主行为及僵王动作；动画时钟及三项存档检查再次通过。未构建或更新 Win7、Android 等其他目标。运动与存档检查证明既有回归通过，不表示所有动作的跨帧率轨迹逐位一致。
