# 前端动画版

视频版本标识为 3.2.5。现有测量仍保留其 3.2.4 来源标记，未冒充新版本复测；预览输出目录沿用原名，保持已打开的本地链接有效。配音文案供网页试听，正式音轨与MP4导出等待确认。

`film.js` 使用 Canvas 2D 绘制真正随时间变化的对象、查询路径、批次、顶点、帧资源和关键帧插值。全部画面由时间直接求值，拖动进度与离线渲染使用同一个函数。25 个段落，共 404 秒；自带中文字幕，无需配音。视频不介绍浏览器播放器实现，角色直接参与讲解。

开场先展示整轮无尽实测的 43.95 → 196.74 FPS，以及对应逻辑更新频率，保留 LP14／用户 11x／同源阵型与不同轨迹等条件，再提出“更多更新，为什么反而花得更少”，进入原理章节。开场和结尾均展示 GitHub 仓库地址，网页上可点击；链接文字直接绘入 Canvas，后续视频导出也会保留。正式配音等待网页预览确认后再生成，API 密钥不得进入源文件或网页。

`reanim-player.js` 直接在浏览器解析原版 1073 `.reanim` XML；省略字段继承前值，平移、两个 skew 轴、缩放、alpha 做相邻关键帧插值，图片及可见性使用前关键帧，按原轨道顺序绘制原 PNG。已装载豌豆射手、向日葵和普通僵尸；僵尸显隐层按普通僵尸配置。身体轨道本来就在原地循环，`_ground` 是业务位移参考，不是图片的父变换，绘制时不重复减去它。根运动示意的基础位移与相位位移均为负，由调用者相加后向左推进，动作周期同步，回绕不跳回。动作名用字符串查找，没有生成枚举。此播放器服务于选定素材的演示，不是完整游戏引擎移植。

`prepare_inputs.py` 从本机 1073 解包资源和原始测量生成 `out/media/performance-v3.2.4-motion/web-inputs.json`。XML 与图片直接嵌入单文件 HTML，脱离服务器也能播放。来源路径、SHA256、筛选规则写入同目录 `web-input-provenance.json`。没有重新测量或修改源文件。

各章按“子弹类型选择 → 碰撞候选 → 轨道身份 → 绘制提交 → 移动一致性 → 计算复用 → 整局验证”衔接。局部测试表的后半段引出下一项具体工作，曲线页保持简短；字幕与后续配音使用的 `storyboard.json` 同步表达这些过渡。

第五章在 3:34 先回看**原版旧算法**：相邻 `_ground` 横坐标差乘动画速率得到速度，再乘本次步长累计到世界位置；速度变化点上的不同取样和浮点累计舍入是两类差异。标题、常驻橙色标签、代码注释和字幕均明确算法归属。速度面积动画使用明确标注的简化示意轨道，不冒充游戏测量。3:58 从 `root-motion-optimization-20261029/after/run1` 与 `run2/accuracy.csv` 读取普通僵尸的同一 60 秒实验，核对两份结果一致后展示 100／120／240Hz 的终点偏差；源定义动画速率12、起点900，数值来自归档，不由画面编造。原版发行程序固定100Hz，这里是原算术多步长重建实验；相位求值的相同终点不代表执行更快。终点偏差横轴明确放大，角色只在该终点原地走动，未伪造60秒运动轨迹。4:10 以明确标注**本项目**的标题与绿色标签，接入整数相位、帧号／余数和周期基础位移的现行方案。

先预览：

```powershell
cd media/performance-video/motion
npm ci
python prepare_inputs.py
npm run preview
```

浏览器打开 http://127.0.0.1:8784/ 。空格或按钮播放／暂停，进度条可拖动，下拉菜单可跳章节。“轨道边框”可以检查组成角色的图片变换。只绑定本机环回地址，不访问外部服务。修改源码后刷新即可。运行 `node build_page.mjs` 则生成可以直接双击播放的单文件网页。

当前用户要求先检查网页，不再自动生成 MP4。下面命令仅在确认画面后手动使用：

```powershell
npm run check-frames
npm run render -- --export-mp4 --fps 60
```

渲染需要本机 Edge、Playwright Core 和 ffmpeg。独立无界面浏览器运行本项目网页；WebCodecs 逐帧编码 H.264，ffmpeg 只负责封装。输出在 `out/media/performance-v3.2.4-motion`，含单文件网页、时间线和渲染报告。

表格沿用上层 `tables.json`；第一章使用 `kFireProjectiles` 二维数据表，展示植物类型和主／副武器如何直接决定子弹类型。数据直接从已归档 `derived-summary.json` 的两次独立进程结果取得（44.04→7.12、44.16→7.12ns），保持“当前表声明／原switch与黄油覆盖模型／共同下游桩”的测量范围，不作为完整开火或原版EXE的耗时。

曲线保留原始 CSV/JSON 样本，不平滑、不补点，暂停／后台／无效区间保留时间缺口。每段使用 1.5 秒 ease-in-out 横向展开，随后停留约 5 秒，总计 6.5 秒；缓动仅影响显露进度，不改变数据坐标，也没有 bounce。电脑展示原版、本项目和精华版的 FPS 与进程 CPU 占用；精华版 FPS 是 CPU 采样时最近的 RTSS 呈现窗口，二者不同步采样，不伪装成完全同一测量区间。电脑未采 CPU 频率，11x 仅为用户设置条件。

手机展示四个 CPU policy 的瞬时频率与整机功耗。功耗图下方固定展示整个有效区间的时间加权平均值（精华版 2.657W、本项目 2.438W），不展示最后一次采样值作为概括。阶梯仅为采样之间的显示保持，不代表中间的真实频率恒定；频率不等于线程驻留。本轮手机记录没有 FPS / CPU 占用，不从其他轮次拼接。放电区间与原脚本一致，时长和加权平均功耗与归档 summary 精确核对。温度与时长差异仍在画面标注。

动画移动速度只是机制示意，不映射实际执行耗时。原版 EXE / 当前生产代码的位宽和 ABI 差异、固定夹具范围、不同整局条件均在画面中说明。精华版比较只出现在视频中，不写入正式性能总账。
